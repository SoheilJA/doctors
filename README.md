# دکترها — پلتفرم سلامت و نوبت‌دهی آنلاین (نسخه نمایشی)

دموی کامل و قابل‌کلیک یک بازارگاه خدمات سلامت فارسی: رزرو نوبت پزشک، مشاوره‌های آنلاین (متنی/تلفنی/ویدیویی)، سفارش آزمایش با نمونه‌گیری در منزل و پشتیبانی تیکتی — همه به زبان فارسی، راست‌به‌چپ، با تقویم جلالی و اعداد فارسی.

> ⚠️ **این یک نسخه نمایشی Frontend-only است.** هیچ backend، API یا دیتابیسی وجود ندارد؛ همه داده‌ها با seed قطعی (deterministic) در استور سمت کلاینت (Zustand + localStorage) ساخته می‌شوند. «پرداخت»، «پیامک»، «بارگذاری فایل» و «درگاه بانکی» همه شبیه‌سازی شده‌اند.

---

## اجرای پروژه

```bash
bun install        # یا npm install
bun run dev        # یا npm run dev
```

سپس http://localhost:3000 را باز کنید.

برای نسخه پروداکشن: `bun run build && bun run start`

نیازمندی‌ها: Node.js 20+ و bun (یا npm).

## ورود به پنل‌ها

صفحه `/login` دو راه ورود دارد:

1. **ورود با شماره موبایل + کد تأیید** — هر شماره‌ای که وارد کنید، هر کد ۵ رقمی پذیرفته می‌شود (شبیه‌سازی).
2. **ورود سریع (پیشنهادی برای مرور دمو)** — چهار دکمه که مستقیماً با کاربران seed شده وارد می‌شوند:

| نقش | کاربر نمونه | مسیر |
|---|---|---|
| 🧑‍🦱 بیمار | علی رضایی | `/patient` |
| 👩‍⚕️ پزشک | دکتر سارا محمدی (متخصص پوست و مو) | `/doctor` |
| 🛡 مدیر کل | محمد کریمی | `/admin` |
| 🎧 پشتیبان | نگار حسینی | `/support` |

از **منوی کاربر** (بالا-چپ هر پنل) می‌توانید بین نقش‌ها جابه‌جا شوید. دکمه **«بازنشانی داده‌های نمایشی»** در همان منو، کل داده‌ها را به حالت اولیه برمی‌گرداند.

## ساختار پوشه‌ها

```
src/
  app/
    (public)/            صفحات عمومی: فرود، فهرست پزشکان، پروفایل پزشک، مجله
    (auth)/login         ورود (موبایل + OTP ساختگی + ورود سریع)
    patient/…            پنل بیمار (داشبورد، رزرو، مشاوره، آزمایش، کیف پول…)
    doctor/…             پنل پزشک (تقویم، ساعات کاری، بیماران، مالی…)
    admin/…              پنل مدیر کل (۱۵ بخش)
    support/…            پنل پشتیبان (تیکت‌ها، SLA، پاسخ‌های آماده…)
  components/
    ui/                  کامپوننت‌های shadcn/ui
    shared/              DataTable، StatCard، ChartCard، StatusBadge، JalaliDatePicker،
                         TicketThread، PanelShell، EmptyState، RatingStars و…
  features/              کامپوننت‌های اختصاصی هر پنل
  lib/                   ابزارها: fa (اعداد فارسی)، jalali (تاریخ شمسی)، schedule
                         (منطق اسلات‌ها)، constants (لیبل‌ها و وضعیت‌ها)، csv، db
  mock/                  مولد داده‌های seed (قطعی و بدون تصادف در هر اجرا)
  store/                 استورهای Zustand (app-store با persist + auth-store)
  types/                 تایپ‌های مشترک دامنه
```

## چه چیزی در دمو ببینید؟

### 🌐 صفحات عمومی
- صفحه فرود با **جستجوی یکپارچه** (تخصص + شهر)، خدمات، پزشکان برتر، مجله و سوالات متداول
- فهرست پزشکان با فیلتر و مرتب‌سازی؛ پروفایل کامل پزشک + دکمه رزرو
- مجله سلامت با مقاله‌های seed شده

### 🧑‍🦱 پنل بیمار
- **ویزارد رزرو ۴ مرحله‌ای**: نوع ویزیت → انتخاب روز (تقویم جلالی — فقط روزهای کاری پزشک فعال‌اند و تعداد نوبت آزاد هر روز نمایش داده می‌شود) → انتخاب ساعت (اسلات‌های واقعی از برنامه پزشک) → پرداخت (کیف پول یا «درگاه بانکی نمونه» با شبیه‌سازی موفق/ناموفق) و دریافت **کد پیگیری**
- نوبت‌های رزروشده از تقویم پزشک حذف می‌شوند و در پنل پزشک ظاهر می‌شوند
- نوبت‌های من (لغو/جابجایی/ثبت نظر)، مشاوره‌های آنلاین با چت، سفارش آزمایش با رهگیری ۷ مرحله‌ای، پرونده پزشکی، اعضای خانواده (رزرو برای دیگران)، کیف پول و شارژ، علاقه‌مندی‌ها، تیکت پشتیبانی

### 👩‍⚕️ پنل پزشک (مهم‌ترین پنل)
- داشبورد با نمودارها (ویزیت ۳۰ روز، درآمد ۶ ماه، نوع ویزیت‌ها، نقشه حرارتی ساعات پرتقاضا)
- **مدیریت روزها و ساعات کاری**: برنامه هفتگی با چند بازه در روز، اعتبارسنجی همپوشانی با zod، تعطیلات، بازه‌های خاص یک روز، **پیش‌نمایش زنده اسلات‌ها** و هشدار تعارض با نوبت‌های رزروشده — تغییرات بلافاصله در رزرو بیماران اثر می‌گذارد
- **تقویم رزروها** (ماه/هفته/روز)، لیست نوبت‌ها با CSV، تاریخچه ویزیت‌ها، صندوق مشاوره‌ها با مهلت پاسخ، بیماران و پرونده، مالی با درخواست تسویه (به مدیر می‌رود)، نظرات با پاسخ، تعرفه‌ها، تنظیمات

### 🎧 پنل پشتیبان
- داشبورد SLA و رضایت، **صندوق تیکت‌ها با نمای جدول و کانبان**، فیلترهای کامل، عملیات گروهی
- تیکت با گفتگوی رشته‌ای، **یادداشت داخلی** (فقط برای کارکنان)، **پاسخ‌های آماده**، واگذاری به عامل، وضعیت/اولویت/دسته، چرخه: باز ← در حال بررسی ← در انتظار پاسخ کاربر ← پاسخ داده شد ← بسته
- پاسخ‌های عامل بلافاصله در پنل بیمار/پزشک (سازنده تیکت) دیده می‌شود و برعکس
- پاسخ‌های آماده CRUD، دانش‌نامه FAQ، عملکرد من

### 🛡 پنل مدیر کل (۱۵ بخش)
داشبورد KPI و قیف تبدیل، گردش‌کار تأیید/رد پزشکان (با دلیل)، مدیریت کاربران و مسدودسازی، نوبت‌ها و مشاوره‌ها (تغییر وضعیت اجباری)، مراکز درمانی، خدمات و تخصص‌ها، امور مالی (تراکنش‌ها، تسویه‌ها با تأیید/رد/پرداخت، قوانین کمیسیون)، کدهای تخفیف، مدیریت نظرات، مجله با ویرایشگر، بنرها، نمای پشتیبانی با SLA، کارکنان و **ماتریس دسترسی‌ها**، گزارش حسابرسی، تنظیمات (شبیه‌سازی‌شده)

## نکات فنی

- **Next.js (App Router) + TypeScript strict + Tailwind + shadcn/ui** — بدون `any`
- **RTL کامل**: فقط utility های منطقی (`ms-*`, `ps-*`, `start-*`…)؛ فونت **وزیرمتن** با `next/font`
- **اعداد فارسی** همه‌جا (`Intl.NumberFormat('fa-IR')`) و واحد پول «تومان»
- **تقویم جلالی** با `date-fns-jalali` و react-day-picker فارسی — هفته از شنبه
- **داده‌ها**: ~۳۰ پزشک در ۱۲ تخصص و ۷ شهر، ۱۲۰ بیمار، ۶۰۰+ نوبت، ۲۰۰+ مشاوره، ۱۵۰ نظر، ۸۰ سفارش آزمایش، ۶۰ تیکت با گفتگو، تراکنش‌ها/تسویه‌ها/بنرها/مقالات… همه با روابط سازگار (درآمد = مجموع تراکنش‌ها و…)
- **دوام داده‌ها**: استور با `persist` در localStorage ذخیره می‌شود؛ تغییرات (رزرو، پاسخ تیکت، تأیید پزشک…) بعد از refresh باقی می‌مانند. دکمه «بازنشانی داده‌های نمایشی» در منوی کاربر هر پنل موجود است
- جداول با TanStack Table (جستجو/فیلتر/صفحه‌بندی/خروجی CSV فارسی)، نمودارها با Recharts، فرم‌ها با react-hook-form + zod (پیام‌های خطای فارسی)، toast با sonner، حالت تاریک با next-themes
- هر لیست: اسکلتون بارگذاری (۳۰۰–۶۰۰ms)، EmptyState و رفتار موبایل (جدول → کارت)

## داده‌های نمایشی و محدودیت‌ها

- همه اشخاص، شماره‌ها، کدها و مبالغ **ساختگی** هستند
- «بارگذاری مدارک/فایل»، درگاه پرداخت و پیامک فقط UI هستند و چیزی ذخیره نمی‌کنند
- ماتریس دسترسی‌ها نمایشی است و مسیریابی واقعی را تغییر نمی‌دهد
- تغییر تعرفه پزشک فقط بر رزروهای جدید اثر می‌گذارد (نوبت‌های seed شده مبلغ خود را نگه می‌دارند)
